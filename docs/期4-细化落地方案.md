## A. 事件分区 + 规模验证

### A.1 目标与现状

- **目标**：events 按月 RANGE 分区 + 分区裁剪实证；千万级事件回放演练（生成 → 全量回放 → 计时断言）；PG 分区为 parquet 冷层导出（后置）铺路。
- **现状**：events 单表（001）；冷层归档按会话 ndjson.gz；风险 #2「事件量增长后 PG 成为瓶颈——分区（表结构已预留）+ 冷层归档」中分区未做。

### A.2 设计

1. **分区**：`events` 按月 RANGE 分区（at 列）——019 迁移：`CREATE TABLE events_partitioned ... PARTITION BY RANGE (at)` + 数据迁移 + 重命名（或直接 ALTER 原表——MVP 事件量下在线 ALTER 可行，无生产）。默认分区 + 按需创建未来分区。
2. **规模演练脚本** `test/scale/gen-events.sh`：批量生成 1000 万事件（copy 协议直插——约 2-5 分钟）→ `回放演练`：ListEventsAfterID 全量扫（水位推进）计时断言（< 预算）+ 按 session 过滤（分区裁剪 EXPLAIN 断言 Index Cond/分区裁剪行数）。
3. **MVP 剪裁**：分区数固定（月粒度）；不自动建未来分区（脚本建）；parquet 导出后置（归档已覆盖冷层需求）。

### A.3 验收

- 迁移幂等（全量重放）；分区裁剪 EXPLAIN 断言；1000 万事件生成+回放计时在 CI 预算内（GitHub Actions 机器实测后定阈值）。

## B. 多宿主 executor 池 + 装箱调度

### B.1 目标与现状

- **目标**：executors 表启用（心跳/能力注册）；api/worker 的路由（lease/健康选 executor）；调度策略缝（默认 round-robin）；多 executor 演练。
- **现状**：executors 表（001）零引用；executor 单实例（compose 一个容器 + 本地二进制）；worker 经 EXECUTOR_URL 单点直连。

### B.2 设计

1. **注册**：executor 启动写 executors 行（id/addr/capabilities/heartbeat_at）——worker 侧心跳检查（>N 分钟无心跳 = 下线）。
2. **路由层**：api 的 ExecutorClient → ExecutorPool（按 session 亲和 + 健康轮询）；沙箱归属 executor_id 落 sandboxes 行（新增列——沙箱操作路由到属主 executor）。
3. **策略缝**：`SchedulerPolicy`（internal/policy）——`Pick(ctx, candidates) → executor`；默认 RoundRobin；参考实现 AffinityBySession（同会话同 executor——沙箱卷本地性）。
4. **多 executor 演练**：compose profile 或 e2e 起 2 个 executor（不同端口）→ 断言负载分布 + 沙箱归属路由 + 单 executor 下线（kill）→ 会话恢复路由到存活者（无卷会话重建——blob/快照恢复链已有）。
5. **MVP 剪裁**：不做装箱（bin-packing 资源配额）——心跳+亲和路由先行；装箱后置（资源量级够大才痛）。

### B.3 验收

- 单测：心跳下线判定、RoundRobin/Affinity 策略、归属路由。
- e2e：双 executor 分布断言 + kill 一个 → 新会话继续（恢复链）。

## C. BYOC 档

### C.1 目标与现状

- **目标**：BYOC 路由层就绪（executors 行 driver=byoc + 镜像模板路由）；镜像构建流水线（模板定义）；凭证就绪即真机 smoke。
- **现状**：E2BDriver 已实现（HTTP API、templateID=镜像名）；无 E2B 凭证未 smoke；无镜像构建流水线。

### C.2 设计

1. **路由层**：executors 行加 driver 维度（docker|e2b|byoc）——worker 的 ensureSandbox 按会话租户的 executor 档路由；api 的 sandbox 创建透传 driver 选择。
2. **镜像流水线**：`deploy/images/` 模板（Dockerfile + 构建脚本 + 推送到租户 registry 的文档化步骤）——MVP：模板 + 文档，不自动构建。
3. **smoke**：`test/e2e/e2b-smoke.sh` 已有——凭证就绪即跑（E2B_API_URL/E2B_API_KEY/E2B_TEMPLATE env）；BYOC 变体同脚本参数化。
4. **MVP 剪裁**：真机验证后置凭证；路由层 + 模板 + 脚本全部 fake 可验。

### C.3 验收

- 单测：driver 路由矩阵（docker/e2b/byoc 选择）；e2e：docker 档路由不回归（现有全部 e2e）；e2b-smoke 脚本语法/参数完备（凭证后置标注）。

## D. 灾备常态化

### D.1 目标与现状

- **目标**：PITR 演练、RustFS 恢复演练、Restate 状态备份演练——进 CI（手动 dispatch + 定期）。
- **现状**：无任何恢复演练；风险 #1（Restate 单点——集群化+备份演练）与 §7 期 4 的灾备项均未落地。

### D.2 设计

1. **PITR 演练** `test/dr/pitr.sh`：pg_basebackup 快照 → 写事件 → 恢复 WAL 到时间点 → 断言事件与时间轴一致（pg 容器的 WAL 归档配置 + 演练脚本）。
2. **RustFS 恢复演练**：归档对象（ndjson.gz）→ 重建会话（物化回放——computeUsage/events 重建链）→ 断言时间轴等价。
3. **Restate 状态备份演练**：restate 卷快照 → 重建 → 挂起审批（awakeable）可继续 resolve（半死 invocation 清空的实证）。
4. **CI 接入**：`.github/workflows/dr.yml`——`workflow_dispatch` + 每周 schedule（快照规模小，分钟级）。
5. **MVP 剪裁**：不自动集群化 Restate（单节点 + 备份演练先行——集群化是部署态后置）。

### D.3 验收

- 三脚本本地全绿 + dr.yml 手动 dispatch 绿；演练时长 < 5 分钟。
