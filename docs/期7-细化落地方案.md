# 期 7：架构边界线细化方案（端口精细化）

> 2026-10-10 立项。输入：六边形边界评审（核心成立，两处过时已核实修正）。
> 状态：已立项，待执行。原则：一次只动一个维度；不引入新状态对象。

## 一、立项依据（评审核实后的净结论）

| 项 | 判定 | 依据 |
|---|---|---|
| Store 端口是漏斗 | ✅ 立项 | 38 方法跨七域 + 接口签名暴露 14 种行类型——抽象层级错误（按表切而非按能力切）；换持久化需重写 40+ 方法 |
| 拆窄接口 + 类型下沉 | ✅ 立项 | 领域类型下沉 core（runs.Run 已备未用）；「可换」是端口的唯一目的——粒度必须按能力 |
| policy 补测试 | ✅ 立项 | 2 测试 vs 202 行——可替换性没有验收（评审的「零测试」过时，但「覆盖浅」成立） |
| 记忆/工具网关、Restate 包装 | ❌ 不立项 | 单一实现=猜测性抽象；分发逻辑非 I/O 边界；Restate 是内核语义不是适配器 |

**评审核实修正**：import store 的文件是 6 个（非 16）；policy 已有 2 测试（非零）。

## 二、执行方案（两阶段，2.5-3.5 天）

### 阶段 1：窄接口定义 + 类型下沉（1.5-2 天）

**7 个窄接口**（定义在 internal/restate 的消费者侧——deps.go 的 Store 字段
拆为组合；每个 5-8 方法，只暴露领域类型）：

```
EventLog         Append / ListAfterSeq / LatestSeq
CheckpointStore  Create / Get / List / Fork / Rollback / Diff
UsageLedger      OrgDailyUsage / QuotaRead / QuotaWrite
SessionRegistry  GetSession / GetAgent / CreateSession / CreateRun /
                 UpdateRunStatus / FinalizeRun
CallLedger       PutLLMCall{Prepared,Result} / PutMCPCall{Prepared,Result} /
                 ListCallsForRun
MemoryStore      Summary* / MemoryItem*
KnowledgeIndex   RetrieveKnowledge / MCPToolAllowed / IsMember
```

**类型下沉 core**：store.Run → runs.Run（core/runs 已存在）；store.Checkpoint
→ core/checkpoint（新建）；store.Summary/Message/MemoryItem → core/memory
（新建）；行类型（SandboxRow/LLMCallRow/MCPCallRow）→ 各域 core 包。
**store 只做 SQL 与映射**。

**验收 A**：internal/restate 对 internal/store 的 import 从 6 → 0；
deps.go 的签名不再出现 store. 类型。

### 阶段 2：适配 + fake 分组 + policy 补测试（1 天）

- **cmd/worker 适配**：*store.Store 适配到 7 个窄接口（适配器函数在
  cmd/worker——组合进 deps 的 7 个字段）
- **fake 分组**：fakeStore 保留单 struct 实现 7 个窄接口（方法按接口分组——
  不改方法体，只动签名与归属；改动量最小化）
- **policy 补测试**：WaitHandleDecide 的 Pick 委托/空候选、QuietWhenIdle
  边界、Decision 序列化（补齐 202 行的覆盖）

**验收 B**：go test ./... 全绿；fake 测试无行为变化（纯签名改造）；
policy 测试从 2 → 6+。

## 三、收益验收（立项的 ROI 证明）

- 换持久化（BYOC 的 SQLite/另一套 PG）从「重写 40+ 方法」→「实现 7 个窄
  接口中需要的 1-2 个」（架构债的量化关闭）
- 加表不再迫使所有 fake 测试改签名（接口按能力切——新表只在对应窄接口
  加方法）
- 领域类型下沉后，core 包成为 kernel 的编译期契约（store 只做 SQL）

## 四、明确不做（本期排除，防范围蔓延）

1. 不新增 harness/executor/MCP 适配器（已有双实现/契约，保持）
2. 不做记忆适配器（单一实现——等 Letta/Mem0 真实需求触发）
3. 不做工具网关（分发逻辑非 I/O 边界）
4. 不把 Restate 包成 DurableEngine 端口（内核语义——单写者/Sleep/
   Awakeable/journal/child workflow 不可抽）
5. 不引入 WaitFor/Goal/WorkItem 的新对象（期 6 已落地的不动）
