# Chronotope 正式版架构：时空可组合持久化运行时

> 版本：v0（规划稿）· 日期：2026-10 · 状态：基于 MVP 全量交付（W1–W8 + P2，评审五项正确性闭合）规划正式版演进
> 前置阅读：`mvp-落地方案.md`（架构决策）、`边界语义设计.md`（产品语义）、`contracts/`（契约）

## 0. 摘要

Chronotope MVP 已验证的核心命题：**一个持久化 agent 运行时可以围绕「事件日志 + durable execution + 会话工作区」三根支柱构建，且真实模型下的多 Agent 协作、人工介入、生态连接全部可闭环**。正式版在此基础上演进为「时空可组合持久化运行时」：

- **时间**：会话是事件时间轴（append-only 真相），run 是 durable journal（重放确定性、断点续跑），快照与归档是时间旅行与冷层回溯的载体——「一周前的会话今天还能继续」已是实线，正式版加「分支、对比、回退」。
- **空间**：会话工作区（沙箱卷）是 agent 的世界状态，与事件日志互为镜像（代码 ↔ 时间轴）；沙箱矩阵从 docker 单档演进到 docker/E2B/BYOC 多档，工作区从卷演进到可寻址 blob 合同。
- **组合**：workflow（顺序）、子 Agent（树）、群聊（黑板）、MCP（外部工具面）四种组合算子已在 MVP 落地；正式版把组合关系本身纳入时空模型（谁在何时在哪个空间发言/写作）。
- **持久化**：事件溯源是唯一真相；投影（usage/记忆/交付清单）可重建；外部效果经 effect ledger 与接纳屏障闭合。

正式版不是重写，而是沿「验证结论 → 补齐生产切面 → 深化时空语义」三条线增量演进（见 §7 迁移路线）。

## 2. 主题阐释：时空可组合持久化运行时

「Chronotope」（时空体）是本架构的一等公民隐喻，四项语义各有实线与正式版目标：

### 2.1 时间（Time）

| 层 | MVP 实线 | 正式版目标 |
|---|---|---|
| 事件时间轴 | append-only events（seq 单调、dedupe 幂等、SSE 续读） | KSUID 时间序 + 分区；时间轴查询语言（按 run/step/tool 过滤） |
| Run 时间 | durable journal（Restate 重放；断点续跑不重复决策） | journal 摘要导出（审计）、重放演练常态化 |
| 会话时间 | 快照含卷恢复（「一周前还能继续」） | **分支**（从任意 seq 派生新时间轴）、对比（两分支 diff）、回退（checkpoint 树） |
| 存储时间 | 冷层归档（parquet 后置）、导出 tar | 分层存储（热 PG / 温 S3-parquet / 冷归档）、按需物化回放 |

### 2.2 空间（Space）

| 层 | MVP 实线 | 正式版目标 |
|---|---|---|
| 会话工作区 | /workspace 卷（沙箱内）+ 文件快路径 | 可寻址 blob 合同（MinIO）：工作区 = 内容寻址对象图 + 目录索引 |
| 沙箱矩阵 | docker（dev）+ E2B（prod 档） | 三档：docker（本地）/ E2B 云（标准）/ BYOC（合规）；能力路由（网络/GPU/镜像） |
| 隔离 | read-only root + tmpfs + network none/bridge + 限额 | 细粒度 egress 白名单、secrets 一次性注入、Kata/gVisor 选项 |
| 资源合同 | TTL + 孤儿 GC | **ComputeLease**：显式持有/释放、按依赖安全回收（评审后置项） |

### 2.3 组合（Composition）

四种组合算子与「组合关系纳入时空模型」：

| 算子 | 拓扑 | MVP 状态 | 正式版 |
|---|---|---|---|
| workflow | 顺序（run_workflow 主循环） | ✅ | 工具循环可配置化（max_turns/maxSteps 按 agent 策略） |
| 子 Agent | 树（spawn_subagent → child run） | ✅ | 结果契约（结构化输出 schema）、预算护栏继承 |
| 群聊 | 黑板（moderator + participants + 共享日志） | ✅ | 任务黑板实体化（§11 后置：卡片单写）、自动组队 |
| MCP/skill | 外部面（mcp: 工具 + skills 文件） | ✅ | MCP 网关（权限/审计/注册表）、stdio 沙箱内进程、skill 版本化 |

### 2.4 持久化（Persistence）

- **真相**：events（append-only）+ journal（Restate state）双真相；投影可重建。
- **外部效果**：effect ledger（exec 幂等缓存已解耦生命周期）+ 接纳屏障（queued 重投）+ outbox（投递退避）。
- **恢复**：快照（镜像+卷）+ PITR（pg_dump 演练已入 chaos 套件）；正式版加 WAL 归档与 MinIO 侧恢复演练。

## 4. 时空模型（正式版核心）

### 4.1 世界状态 = 事件投影 + 工作区内容

每个会话有两个互为镜像的事实面：

1. **时间面**（events）：append-only、seq 单调、dedupe 幂等；SSE 续读；可导出/归档/回放。
2. **空间面**（workspace）：沙箱卷（MVP）/ blob 对象图（正式版）；文件写操作是事件（sandbox.exec payload 含 path/sandbox_id），时间轴可还原「谁在何时写了什么」。

正式版把两个面**统一寻址**：`(session_id, seq)` 定位时间点；`(session_id, path)` 定位空间点；`checkpoint(session_id, seq)` 把二者钉在一起——**这是「时空体」的落地形态**：checkpoint 树就是时空坐标系统。

### 4.2 Checkpoint 树（时间旅行）

- 自动 checkpoint：run 边界 + 里程碑（每 N 步/消化后）→ 快照（镜像+卷 tar，MVP 已实现含卷）+ 事件 seq 指针。
- 分支：`fork(session, at=seq)` 派生新会话（共享前缀真相，写时复制——事件前缀共享、工作区层 copy-on-write）。
- 对比/回退：两分支 diff（事件差集 + 文件 diff）；回退 = 把 HEAD 移回 checkpoint（新事件追加，不改历史——真相不可变）。
- 审计：审批/冻结/取消/群聊发言全部在时间轴上（audit.* 事件 + approver/digest 留痕，MVP 已落地基础）。

### 4.3 组合关系入时间轴

- group.turn 事件（发言者归属）、subagent.spawned/completed（父子 run 归属）已在时间轴——正式版加**拓扑视图**：会话的 run 树/发言图（谁派生了谁、谁在谁的指令下发言），控制台可点击跳转。
- MCP/skill 的安装与调用（mcp.connected/mcp.call/skill.install）已在时间轴——工具面变更可追溯、可回放。

## 5. 正式版功能面（分域规划）

### 5.1 运行时域

- **执行策略可配置**：max_turns/maxSteps/consolidate 阈值/预算从硬编码变 agent 策略对象（config 版本化已有）。
- **structured output 结果契约**：run 终态支持 JSON schema 校验（子 Agent/群聊结果消费）。
- **journal 审计导出**：run 的 harness 调用序/工具序/重放键摘要——合规与调试。
- **取消语义升级**：非抢占式已落地；正式版加抢占式（工具执行中取消 → executor 的 exec 中止信号）。

### 5.2 空间域

- **ComputeLease**（评审唯一未闭合项）：executor 维护租约账本——`acquire(session, resources)` / `renew` / `release`；沙箱回收先查依赖（run 挂起/等待中的 session 不得回收）；TTL 只做泄漏兜底。
- **工作区 blob 合同**：MinIO 内容寻址 + 目录索引（替换 executor 本地 externalize）；沙箱挂载只读对象图（或按需拉取）。
- **egress 白名单**：network 三档（none / 白名单域名 / 全开）按 agent 策略 + 审计。
- **BYOC 档**：E2B BYOC 或自建 Firecracker 池；镜像构建流水线（模板 v2）。

### 5.3 记忆域

- 三层记忆：工作（消息窗口）/ 长期（memory_items 条目）/ 共享（org 级知识库，pgvector）。
- 消化策略化：阈值/主题/摘要版本滚动已落地；正式版加**摘要质量评估**（摘要后任务完成率回归）与**遗忘**（TLL 条目淘汰）。
- 记忆与时间旅行联动：fork 分支继承记忆快照；回退撤销消化影响（摘要带源 run 版本，回退可重放）。

### 5.4 治理域

- **用户层**：api_keys 挂 user（表已预留 scopes）；user 级配额/限流（限流器 org/user 桶已备）。
- **审批升级**：digest+审批者已落地；正式版加审批策略（按 tool/风险/金额阈值路由审批人）、过期自动拒绝。
- **审计合规**：audit.* 事件全覆盖（审批/取消/冻结/预算/投递）→ 导出与留存策略。

### 5.5 运营域

- **冷层归档**：events 按 session 归档 parquet（MinIO）+ 摘要清单；投影（usage/记忆）在归档前固化；按需物化回放。
- **usage 增量 rollup**：水位 + 增量累加（替换全量重建），幂等靠事件水位。
- **投递真集成**：outbox 已就绪——接 SMTP/IM webhook 的生产配置 + 退避监控。
- **可观测性**：OpenTelemetry 埋点（run 跨度 = 会话时间轴的 OTEL trace 映射）、指标（北极星：utilization = 活跃秒/墙钟秒）。

## 6. 前沿生产方案对照（联网调研结论，2025–2026）

### 6.1 持久化执行引擎：保持 Restate（并升级部署形态）

- **Restate vs Temporal**（[官方对比](https://restate.dev/vs/temporal)，2026-09 更新）：两者同为生产级；Restate 的差异化 = 单二进制集群（Temporal 需 Frontend/Matching/History/Worker 四组件 + 外部 DB）、步进开销 <10ms P99（Temporal 每步经任务队列派发）、Virtual Object 一等公民（Temporal 需长活 workflow + Continue-As-New + asyncio.Lock 手工协调）、BYOC（Temporal Cloud 无）。
- **关键案例**：[Replit 将 Replit Agent 从 Temporal 迁到 Restate](https://restate.dev/vs/temporal)——单次 agent 执行数千个内联 durable 步骤、每步毫秒级落账、tens of cells/25k durable actions/s/cell。这直接验证了本项目的架构选择：**agent 主循环内细粒度持久化（每 LLM 调用/每工具调用一个 journal 步骤）是可行且被大规模验证的**。
- **Durable execution ≠ exactly-once**（[Diagrid FAQ](https://www.diagrid.io/faq/durable-execution/does-durable-execution-guarantee-exactly-once-execution-for-ai-agent-tool-calls)）：重放可能重复调用工具；必须幂等键或对账模式——这正是本项目评审 #1/#2/#3 已闭合的（prepared/done 状态机 + 输入摘要 + effect 账本解耦）并构成正式版的固定防线。
- **Thoughtworks 技术雷达**将 Restate 列入 Trial（[radar](https://www.thoughtworks.com/en-es/radar/platforms/restate)）；社区评估报告（[restate-evaluation](https://github.com/bobmatnyc/trusty-tools/blob/main/docs/trusty-agents/research/restate-evaluation.md)）与 [2026 三引擎对比](https://www.pkgpulse.com/guides/temporal-vs-restate-vs-windmill-durable-workflow-2026) 均将 agent 会话场景指向 Virtual Object 模型。
- **对照结论**：正式版保持 Restate；增量在部署形态——单节点 dev → 集群（多实例 + 对象存储快照）→ Restate BYOC（合规与成本）。风险清单 #1（单点）由此升级为「集群化 + journal/对象状态备份演练」（期 1）。

### 6.2 沙箱矩阵：镜像+卷+快照三态（对照 E2B/BYOC）

- E2B 参考实现：Firecracker microVM、pause/resume（暂停停计费）、snapshot/fork（含内存与进程）、[BYOC](https://docs.e2b.dev)（Devin Outposts 案例）；隔离梯度共识 = Docker（快弱）/ gVisor（中）/ 微虚拟机（强，<125ms 启动）（[Northflank 对比](https://northflank.com/blog/how-to-sandbox-ai-agents)）。
- 持久化分层共识：**不可变镜像 + 租户卷 + 会话快照/overlay 检查点**；[Cloudflare Sandboxes](https://developers.cloudflare.com/sandbox/sdk/concepts/backup-restore/) 生产实现为 squashfs 只读 lower + FUSE overlayfs 可写 upper。
- **对照结论**：本项目已落地「镜像 + 卷 + 快照含卷（评审 #7）」三态与 docker/E2B 双档——正式版补第三档 BYOC（合规）、egress 白名单三档、ComputeLease（唯一未闭合项）。

### 6.3 记忆架构：memory blocks + 后台巩固（对照 Letta）

- [Letta（MemGPT）](https://docs.letta.com) 确立 memory blocks 范式：Core（常驻）/ Archival（向量+关键词，pgvector）/ Recall（会话历史可休眠）；sleep-time agent 后台巩固；[memory omni-tool](https://www.letta.com/blog/introducing-sonnet-4-5-and-the-memory-omni-tool-in-letta/) 让模型主动读写；shared blocks 跨 agent 挂载。
- 向量库共识：先 pgvector（同库事务 + RLS 租户隔离），规模化再专用库（[clickhouse 规模化对比](https://clickhouse.com/resources/engineering/scale-vector-search-postgres)）。
- **对照结论**：本项目的分层记忆（主题摘要滚动 + 内容哈希条目 + 检索注入 + 消化阈值）正是 blocks 范式的轻量实现；正式版补「记忆块可寻址/可共享（org 级）+ 巩固时机策略化（会话边界/token 阈值/空闲 heartbeat）+ 记忆与时间旅行联动」。

### 6.4 MCP 生产化：无状态服务器 + 网关治理

- 规范演进：[2025-06-18 Streamable HTTP](https://modelcontextprotocol.io/specification/2025-06-18) 取代 HTTP+SSE（单端点/断线重连/可无状态升级）、会话语义、OAuth 2.1 + resource indicators；2025-11-25 增会话管理与 Origin 校验（防 DNS rebinding）；2026 EMA 集中授权（[InfoQ](https://www.infoq.com/news/2026/07/mcp-ema-enterprise-auth/)）。
- 生产形态：**stateless MCP server 为默认，有状态会话由 runtime 恢复**；企业经网关统一身份（workload identity）、工具 allowlist、审计（[Aembit](https://aembit.io/blog/enterprise-at-scale-mcps-emerging-identity-and-governance-foundation/)、[mcp-gateway-registry](https://github.com/agentic-community/mcp-gateway-registry)）。
- **对照结论**：本项目的 MCP 客户端（worker 托管、tools/list 缓存、schema 透传、mcp.call 审计事件）与「状态归 runtime」共识一致；正式版补 Streamable HTTP 会话语义对接、MCP 网关（租户级授权/白名单/审计）、stdio 沙箱内进程（落地方案 §11 后置）。

### 6.5 多租户计费与协调拓扑

- **计费**：LiteLLM 是开源网关事实标准（virtual keys/teams/预算熔断/spend 追踪，[docs](https://docs.litellm.ai/docs/proxy/users)）；计量双轨 = token（input/output/cached）+ 计算秒 + 快照存储；开源计费引擎 [OpenMeter](https://openmeter.io)/[Lago](https://github.com/getlago/lago)（含 Agent SDK 打点）。**共识：预算/配额是一等资源，熔断与生命周期联动——预算耗尽即 pause 沙箱并快照现场**。
- **对照结论**：本项目的三级熔断（run/org 预算 + 冻结 awakeable 槽）已实现「预算耗尽→冻结现场」的语义雏形；正式版把快照/卷的「时空占用」并入同一账单（计量事件流 → 计费引擎 → 配额熔断）。
- **协调拓扑**：三种生产拓扑（群聊/黑板、树形委派——Claude Code subagents 有深度上限、[Anthropic orchestrator-worker](https://www.anthropic.com/engineering/multi-agent-research-system)、swarm）；[A2A 规范](https://a2aproject.github.io/A2A/specification/)（AgentCard 发现、Task 状态机、artifact+push，2025 捐 Linux 基金会）的边界原则——**「任务状态共享、agent 内部状态私有」**。
- **对照结论**：本项目的三种拓扑（workflow 顺序/子 Agent 树/群聊黑板）齐备；正式版把 A2A 的边界原则落为内部约定：**协调层只传引用（sandbox id / memory block ref / artifact ref），状态零复制**——这正是「时空可组合」的落地语义（§4.1 的统一寻址 + checkpoint 树）。

## 9. 附录：MVP 验证结论清单（正式版决策依据）

1. 真实模型下工具调用协议必须带参数 schema、tool_call_id 成对、片段按 index 合并（六个 fake 绿/真实红雷——正式版 harness 协议回归矩阵必须含这些用例）。
2. 真实 moderator 服从主持协议但收敛纪律差——**决策护栏（轮次上限移除工具）是生产必需**。
3. 审批必须绑定动作摘要与审批者（audit.approval）。
4. 快照必须显式打包 named volume（docker commit 不含卷）。
5. 事件/消息写回必须幂等（journal 重放安全）；消息历史必须升序。
6. 接纳屏障（queued 重投）与 effect ledger（解耦沙箱生命周期）是崩溃恢复的两道必设防线。
