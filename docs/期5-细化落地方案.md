## A. 多租户管理面

### A.1 目标与现状

- **目标**：org/成员/用量/配额/账单的统一管理 API（面向控制台与外部计费系统）。
- **现状**：orgs/users/API keys 表存在且 API 有散点端点（创建 org/key、预算策略）；**缺**：成员管理、用量查询聚合端点、配额读改、账单导出（CSV/事件级）、org 级审计列表。

### A.2 设计

1. **管理 API 收敛**：`GET/POST /orgs/{org}/members`（邀请/角色——复用 principal 化：member 绑定 user）、`GET /orgs/{org}/usage?granularity=hour|day|month`（usage 表聚合——计量原语已有）、`GET/PUT /orgs/{org}/quota`（daily_token/compute_seconds——层 0 原语的读改面）、`GET /orgs/{org}/billing/export`（CSV 事件级导出——审计导出已有 org 版，扩展用量维度）。
2. **角色模型**（层 2 参考业务）：org_admin / member / auditor——审批策略的 approver 集合即成员（期 3 §B 已有成员概念雏形）。
3. **MVP 剪裁**：不做订阅/支付集成（外部计费系统对接后置——账单导出是边界）；成员邀请不做邮件流（管理 API 直建）。

### A.3 验收

- 单测：成员 CRUD/角色、用量聚合（hour/day/month）、配额读改、CSV 导出
- e2e：管理面完整链路（建 org → 加成员 → 跑用量 → 查聚合 → 导出）

## B. 控制台完整度

### B.1 目标与现状

- **目标**：控制台覆盖管理面——用量看板（三轴图表 + 时间聚合）、org/agent 管理页、审计事件流（approval/mcp 审计的只读视图）、成员管理。
- **现状**：会话列表/时间轴/审批回调/时空视图（checkpoint/fork/rollback/run 树）/记忆已有；管理面缺。

### B.2 设计

1. **用量看板**：折线/柱状（token/计算秒/活跃秒——usage 表聚合端点 §A 驱动）+ org 级配额进度条。
2. **管理页**：org 设置（成员/配额/API keys）+ agent 列表 CRUD（现有 API 已有——补 UI）。
3. **审计流**：audit_events 表的只读时间轴（approval/mcp/limit 事件——期 3 已写库）。
4. **MVP 剪裁**：不做成员邀请邮件流；audit 流做只读视图（搜索/过滤后置）。

### B.3 验收

- Playwright：用量看板渲染、org 管理页 CRUD、审计流展示——三 profile（console/tt/runtree）不回归。

## C. 可靠性 SLA 化

### C.1 目标与现状

- **目标**：SLA 目标定义 + 量级触发预案（期 4 后置项转为「触发即执行」的预案文档 + 演练脚本钩子）。
- **现状**：运维基准（资源峰值/演练耗时/注意事项）已有；parquet/装箱/Restate 集群化的触发条件已写明但无执行预案。

### C.2 设计

1. **SLA 目标**：run 提交 P99 < Xs（基准测量）、SSE 首帧 < Xs、恢复演练 RTO/RPO 目标（演练实测基线：PITR 恢复 < 3 分钟、restate 卷恢复 < 1 分钟——写入 SLA 文档）。
2. **触发预案**：每个量级后置项写「触发信号 → 执行步骤 → 验证」（parquet：归档量 > N GB；装箱：executor 池 > N 宿主；集群化：可用性要求）。
3. **演练钩子**：dr.yml 扩展「月度全量演练」（每周已 dispatch——月度加 PITR 时长基线断言）。
4. **MVP 剪裁**：不实现 SLO 监控告警（外部可观测系统对接后置——先定目标与基线）。

### C.3 验收

- SLA 文档（目标 + 基线实测）+ 预案文档（触发信号/步骤/验证）+ 月度演练 workflow。
