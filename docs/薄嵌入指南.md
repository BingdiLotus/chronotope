# 薄嵌入指南（M5——竞品从「平台」变「依赖」）

> 2026-10-09。目标：让用户自带 Claude Agent SDK / OpenAI Agents SDK / Pi /
> dsh 的 harness，用 Chronotope 的幂等与对账语义（不要求跑完整平台）。

## 形态

```
┌─────────────────────────────────────────────┐
│ 你的 agent 框架（Claude/OpenAI SDK、Pi、dsh）│  ← 用户自带
├─────────────────────────────────────────────┤
│ /runs 协议适配层（参考 harness/app/main.py） │  ← 薄适配（本指南）
├─────────────────────────────────────────────┤
│ sdk/thinruntime（Go）：EffectKey + LedgerClient │  ← 嵌入的幂等/对账原语
└─────────────────────────────────────────────┘
     ↓ /runs 协议（0 平台改动换 harness）
Chronotope 平台（可选）：effect ledger + 审计链 + 对象模型
```

## 三步接入

1. **幂等键**（每次模型调用与工具副作用必须携带——与平台同构）：

```go
k := thinruntime.EffectKey{RunID: "r_1", Step: 3, Tool: "bash", ID: "t_9"}
k.HarnessKey() // "r_1:3"——模型调用幂等
k.ToolKey()    // "exec:3:t_9"——工具副作用幂等
```

2. **崩溃恢复的对账**（重放前查账本——result 回读 / unknown 停住）：

```go
c := &thinruntime.LedgerClient{BaseURL: "http://platform:8080"}
rows, admission, _ := c.Reconcile(ctx, "r_1")
for _, r := range rows {
    switch thinruntime.Decide(&r, reqHash) {
    case "replay":  // result 同 hash → 回读原结果（不执行）
    case "halt":    // unknown/dispatched → 停住人工裁决（不重跑副作用）
    case "conflict":// 异 hash → operation 冲突拒绝
    }
}
```

3. **自证兼容**：`go test ./test/contract/`（协议帧级一致性——delta 序 /
   tool_call / done 唯一终态 / 未知帧拒绝）。

## 与 Kitaru 的对比

| | Kitaru（薄运行时包住框架） | Chronotope 薄嵌入 |
|---|---|---|
| 形态 | 把框架跑进运行时 | 幂等键 + 对账原语嵌入框架 |
| durability | ✅ 依赖框架/自建 | ✅（可选接平台——journal 实证） |
| **可对账性** | ❌（重放策略是声明式） | ✅ **effect ledger 的 prepared/result/unknown + 对账 API**——副作用是否发生可查询 |
| 审计 | 无 | 平台侧哈希链（可选） |

**核心差异**：Kitaru 解决「框架怎么跑」，Chronotope 薄嵌入解决「**跑完怎么证明副作用只发生一次**」——后者是合规与钱的场景。

## 参考集成（Pi / OpenAI Agents SDK 的 /runs 适配）

内置 harness（harness/app/main.py）就是参考实现：任意 agent SDK 的 run 循环
映射到 /runs 的请求/SSE 帧（delta/tool_call/done/beat/error）——协议见
[docs/contracts/runs-protocol.md](contracts/runs-protocol.md)。幂等由 worker
侧 journal 缓存承担（harness 无状态三铁律不变）。
