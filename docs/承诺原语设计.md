## 0. 定位

**承诺（commitment）是一等的、可审计的、跨平台可见的 agent 义务记录。**

它不是「记忆的一部分」，不是「消息元数据」，是独立实体——与 run / event / session 并列。它比记忆更硬（不可撤销、不可重算、外部有副本），比消息更结构化（有准入判据、有状态机、有违约定义）。

### 与内核其他构造的关系

| 构造 | 语义 | 可变性 | 承诺的差异 |
|---|---|---|---|
| **event** | 已发生的事实 | append-only，但不保证外部可见 | 承诺是**对外承诺**，外部有副本（Slack 消息） |
| **memory** | agent 知道什么 | 可重算、可更新、可遗忘 | 承诺不可撤销，违背要留痕 |
| **message** | 对话历史 | 按线程存储，不跨平台 | 承诺跨平台可见（agent 级） |
| **session_waits** | 任务在等什么 | 按 run 生命周期存活 | 承诺按 agent 生命周期存活 |
| **goal** | 任务分解的义务（027 迁移） | 对内、可仲裁 | 见 §1.5 的边界 |

**核心差异**：承诺是唯一一个「说出去就成真、外部可追责、跨平台一致」的构造。这一点决定了它的实现必须比记忆更严格。

## 1. 理论依据

（原文不变：Hamblin/Walton & Krabbe 承诺店、Castelfranchi 四分类、Bentahar CAN 状态机、Colombetti 的 coherence 判据、四元组抽取 91.5%+、李福春「状态在副作用之前写 + 独立对账器」。关键推论三条不变：承诺是成熟理论搬进新载体；准入判据有标准答案；违约用 coherence 而非 truth。）

### 1.5 与 goal 的边界（第一轮硬伤 ①——必须先划清）

chronotope 已有 goal 的一等实体（027 迁移：version + state_hash + arbitration）——「义务」语义已有一份。两个义务实体并存必须划清边界，否则仲裁混乱：

| 维度 | goal | commitment |
|---|---|---|
| 义务方向 | **对内**（任务怎么拆、谁来做） | **对外**（对 counterparty 说了什么） |
| 产生方式 | 显式创建（API/仲裁） | 出站言语行为的抽取 |
| 生命周期 | run 内推进、可仲裁改写 | agent 级、不可撤销 |
| 判据 | 完成/失败（state_hash 校验） | coherence（自相矛盾/撤回才是违约） |
| 撤销 | 可仲裁（027 的 arbitration） | 不可撤销——canceled 是「明确说撤回」不是「改主意」 |

**一句话划界**：「我明天给你答复」同时产生 goal（对内：要做答复这件事）和 commitment（对外：向 A 承诺了答复）——**goal 管「这件事做没做」，commitment 管「这句话还算不算数」**。两者可关联（goal_id 引用）但不可合并。

## 2. 核心设计

### 2.1 承诺是事件，不是行

**承诺的写入/兑现/违约全部是 event，`agent_commitments` 表是投影。**

```go
// 事件类型（加入 event.Type 全集——只增不改纪律；链序已按行序，
// 新事件类型能进哈希链）
const (
    AgentCommitted        Type = "agent.committed"         // 创建承诺
    AgentCommitmentKept   Type = "agent.commitment_kept"   // 兑现
    AgentCommitmentBroken Type = "agent.commitment_broken" // 违约
)
```

**为什么是事件而非行状态**（原文表格不变：重放安全、时刻精确、全链可审计）。

**投影表**（派生数据，不是真相）：

```sql
CREATE TABLE agent_commitments (
  id             text PRIMARY KEY,        -- 承诺 ID（幂等键）
  agent_id       text NOT NULL REFERENCES agents(id),

  -- 可追溯性
  made_in_thread text NOT NULL,          -- 在哪个线程说的
  made_in_run    text REFERENCES runs(id),
  made_at        timestamptz NOT NULL,

  -- 对象
  counterparty   text,                    -- person_id（见 §4——多平台后置）

  -- 内容
  speech_act     text NOT NULL,           -- commissive / assertive / directive
  content        text NOT NULL,
  content_digest text NOT NULL,           -- sha256(content)——字节级判重（见下）
  decider_confidence numeric,             -- 准入门的校准概率（审计用——见 §2.3）

  -- 时间约束
  due_at         timestamptz,

  -- 状态（由事件派生）
  state          text NOT NULL DEFAULT 'open',  -- open / fulfilled / broken / expired / canceled
  resolved_at    timestamptz,

  -- 可见性
  visibility     text NOT NULL DEFAULT 'agent',  -- agent（跨平台） / thread（线程内）

  INDEX idx_agent_commitments_open (agent_id) WHERE state = 'open',
  INDEX idx_agent_commitments_due (due_at) WHERE state = 'open' AND due_at IS NOT NULL
);
```

**判重语义修正（第一轮硬伤 ②）**：

- `content_digest = sha256(content)` 是**字节级判重**——只能去「逐字重复的消息」（重复发送的同一句话）。它**不能**实现「语义相同措辞不同只记一条」。
- **语义判重后置**：那是相似度检索（向量层或语义门——另一个子系统），不在第一阶段。第一阶段诚实承认：字节级去重 + 语义判重标注为后置项。

**迁移号**：`migrations/036_commitments.sql`（现有 030-035 已占用——mcp_duration/steers/extensions/credential_ref/credentials/credential_events）。

### 2.2 状态机

（原文不变：open → fulfilled/broken/expired/canceled；expired → fulfilled 晚兑现；终态不可转移；违约定义是撤回或自相矛盾，不是「晚了」。）

### 2.3 准入：两段式（decision 门 → 完整抽取）

**不能靠触发词**（脆且漏），但**也不能每个消息都做完整 LLM 抽取**（成本失控）。两段式：

```
每出站消息
  ↓
① decision 门（~100 token、70-500ms、$0.0000042-0.00001/次）
   is_commissive？（predicate/Noul）
   strength 分级？（choice/score）
   是否对外（有 addressee）？（predicate）
   判定为负 → 结束（大部分消息在这里终止，零完整抽取成本）
   判定为正（预期 ~10% 消息）
  ↓
② 完整四元组抽取（LLM——只在判定为正时发生）
   speech_act / strength / content / addressee / temporal_marker
```

**decider 策略缝**（与 harness 适配器同构——可替换）：

```go
type CommitmentDecider interface {
    // 准入判据：这条消息是否产生承诺义务 + 强度分级 + 置信度
    Decide(ctx context.Context, message string, counterparty string) (AdmitDecision, error)
}

type AdmitDecision struct {
    IsCommissive   bool     // 判定为承诺类言语行为
    Strength       string   // strong / weak / conditional
    Confidence     float64  // 校准概率（进审计——群体口径）
    Reason         string   // 判据说明（可审计）
}
```

**三个实现**（第二轮调研结论）：

| 实现 | 场景 | 约束 |
|---|---|---|
| **OpenAI Decisions API**（gpt-6-luna） | **默认（中文场景优先）** | beta；$0.10/M 输入无输出费；OpenAI 兼容（现有代理可走） |
| **Jev**（TypeSafe System One） | 英文场景（成本低 2.4 倍） | **中文概率校准退化（官方明确）**；非 OpenAI 兼容（/v1/systemone——poke2api 走不通，需独立透传）；钉版本 jev-1.13.0 |
| **本地小模型/规则** | 离线/成本敏感 | 召回优先的阈值自调 |

**决策要点**：
- decision 模型「输出永远在选项内」的结构性保证，恰好使它**做不了 content/addressee/temporal 的自由文本抽取**——这就是为什么完整抽取不能省，只能**降频**（判定为正才做）。
- **召回优先**：承诺漏记（把承诺当断言）比误记（把闲聊当承诺）危险——低阈值高召回 + `decider_confidence` 落审计。
- content 的降级方案：判定为正后 **content 先引用原消息全文**（span 抽取后置）——先有全量、后有精化。

**完整抽取器**（只对判定为正的消息运行）：

```go
type CommitmentCandidate struct {
    SpeechAct          string    // commissive / assertive / directive / declarative
    CommitmentStrength string    // strong / weak / conditional
    Content            string    // "明天给你答复"
    Addressee          string    // person_id（对谁承诺）
    TemporalMarker     string    // "明天" / "下周三" / ISO8601
    DueAt              *time.Time // 解析后的绝对时间（相对日期在代码里算，不交给模型）
}
```

**失败方向反转（第一轮硬伤 ③）**：

- 文档 3.2 原文「承诺写入失败不阻断消息发出」**反转**——对「不可撤销的义务记录」，义务记录失败时默认**阻断出站**（或强告警 + 明确的 allow-list 例外）。「说出去了但承诺没记上」的镜像孤儿比「承诺了但没说出口」更危险（后者可 reconciler 补发，前者义务丢失无痕）。
- 两个方向的孤儿 reconciler 都要有（3.2 原文只提了一个方向）。

**成本预算（第一轮硬伤 ④——量化）**：

| 路径 | 每消息成本 | 备注 |
|---|---|---|
| decision 门 | $0.0000042（Jev）/ $0.00001（OpenAI） | ~100 输入 token、70ms |
| 完整抽取（仅判定为正 ~10%） | $0.001-0.005/次 | 摊销后 ≈ decision 门的 1/10 频率 |
| 合计 | **每消息 ~$0.0001 量级** | 比「每消息完整抽取」降一个数量级 |

## 8. 一句话总结

**承诺是 agent 对外义务的一等实体，以事件为真相、投影表为查询面、reconciler 为兑现机制；准入是两段式（decision 门降频 + 判定为正才完整抽取），违约用 coherence 判据；与 goal 划界（对内义务 vs 对外承诺），与现有 journal/event/recovery 机制同构。**

它不是「记忆的加强版」，是独立维度——记忆可以错可以忘，承诺不行。它的存在让「多平台言行一致」从不可判定变成了可查表，这是 chronotope 作为「长活 agent 基础设施」的真实价值。
