# 安全白皮书章节：信任拓扑（期 6 ② + 九期 5.2 修订）

> 2026-10-10 修订（审计 5.2）：Trust 标注是提示防御，**不是执行权限**——
> 行动权来自 Bot ActionIntent/ExecutionGrant、Broker 与应用 owner 的当前
> 授权/command receipt。

## Ingress 树（信任等级）

```
入站载荷
├── OPERATOR_AUTHORITY（已认证控制台/审批回调——approver 集合校验 + TTL）
│    可授权：class 0/1/2 全谱动作
└── UNTRUSTED_DATA（webhook payload / 不可信 issue / MCP 返回内容）
     可读作：证据（模型可见——文字前缀标注）
     不可授权：class 2 破坏性动作——强制审批且审批必须来自 operator
```

## 强制规则（机器检查）

1. **MCP 返回 = untrusted**：结果消息 Source=untrusted + Content 文字前缀
   ——内容级信任标记（提示防御：模型可读作证据）
2. **class 2 的授权链**：强制审批 + approver 集合 + digest 绑定 + TTL——
   不可被 untrusted 自证
3. **明确边界（九期 5.2）**：Source 不传给模型（harness 协议只收
   content/role）——文字前缀是模型唯一可见的信任信号；**标签不能证明一般
   外部写被阻断**（默认 bash/python/write_file 为 class 1——权限隔离靠
   class 分级与审批，不靠 prompt trust）

## 与已有资产的同族关系

- 工具级准入（MCP allowlist）→ 内容级信任（提示防御）→ 动作级审批
  （risk class + HITL digest——**权限的实际执行点**）
- 「审批必须绑定动作摘要」与「指令必须绑定信任等级」是同族问题，但
  **信任等级是提示、审批是权限**——不混用

## 首发安全姿态（九期 5.2 采纳）

- 关闭任意外网写与未审查的通用工具（class 分级收紧——不依赖 prompt
  trust 代替权限隔离）
- 技术 wait 保存可信出处与被冻结 continuation；业务目标与恢复解释来自
  owner（intent 的硬编码文本不冒充可信来源）
