## 逐项评估

### §A WaitFor 具名原语——**降级为文档（不做工程）**

- 四底座已是行业标配能力的等价实现（Restate awakeable 就是 operator_input
  形态、Sleep 就是 timer 形态）——收敛成具名原语是**内部命名一致性**，
  **买家不可见、不为此付费**——价值 = 认知收益，成本 = 表+原语+四断言（2 天）
- 决策：降级为 **docs/等待语义对照.md**（四种唤醒与 WaitFor 四 wake kind 的
  语义对照 + 「唤醒→查→判定」的现状说明——半天文档化，认知收益保留）

### §B yield intent 捕获——**后置（触发式）**

- 解决「决策蒸发」的真实漂移，但**价值在真实长周期场景出现时兑现**——
  当前无真实多日客户（M3 demo 场景不需要多日挂起）
- 决策：触发条件 = 「首个真实多日运行的客户场景」（与 G 类量级触发同款）
  ——届时与 causal slice 的质量优化一起做（那时有真实需求驱动字段设计）

### §C 信任拓扑——**值得立即做（唯一）**

- **真实市场焦虑**（OWASP/威胁矩阵背书——企业安全采购的既有话题）
- **与现有资产同族扩展**（risk class + HITL digest 绑定——「审批绑定动作
  摘要」的同族：补「指令绑定信任等级」）
- **可销售**（安全白皮书章节——六份评审反复说的「卖合规」路线的延续）
- 范围收紧：不是完整 ingress 树——是**一条强制规则**（不可信输入不能授权
  class 2 动作）+ 反例测试 + 白皮书章节（1-2 天）

## 修订后的执行（评审核实后）

```
1. §A+§B 合并（1.5-2 天——session_waits 表含 intent/expect + Decide 从
   QuietWhenIdle 启发式升级为查 WaitHandle 的可判定版本；e2e 只做
   timer + operator_input 两条——覆盖现有真实场景）
2. §C 信任拓扑（1-2 天——照原样）
```

排序理由：DECIDE 是自己经济学基线认定的毛利开关——先完成毛利开关，再做
白皮书。

## 方法论注记

本评估的价值框架：**价值 = 解决的痛点 × 买家付费强度 × 与现有资产的杠杆**。
- §A 杠杆高（已有底座）但买家付费强度零 → 不做工程
- §B 痛点真实但当前无买家场景 → 触发式
- §C 痛点真实（市场焦虑）+ 有据可依（威胁模型）+ 同族扩展可销售 → 做

「值得做」不等于「方案里的每件都做」——方案的职责是列出候选，评估的职责
是把候选对买家付费的映射算清楚。
