# 凭据服务设计（Credential Reference + Resolver + 审计轮换）

> 2026-10-12 设计定稿（先调研后文档）。目标：Chronotope 的凭据能力对齐
> Claude managed agent / OpenAI Agents / dsh 的凭据服务形态——**引用进
> 快照、值进 resolver、使用进账本**。
> 调研核实：OpenAI Agents 的 [Vaults](https://developers.openai.com/api/docs/guides/agents-api/tools/vaults)
> （vault credential 的引用形态——agents 引用凭据不嵌值）；dsh 的
> [credentials 子系统](https://github.com/deepseek-ai/deepseek-harness/blob/main/docs/subsystems/credentials.md)
> （CredentialRef = POSIX 环境变量名的 nominal brand + resolve/describe
> 双面 + source 层优先级 + reference-updated 事件）；Claude Code 的
> managed/OAuth 流（平台级登录态）。

## 一、调研结论（三平台凭据形态对比）

| 维度 | OpenAI Vaults | dsh credentials | Claude managed |
|---|---|---|---|
| 引用形态 | vault credential 的引用（agent 配置引用凭据 ID） | `CredentialRef` = POSIX env 名（**nominal brand 防混用**） | OAuth 登录态（平台托管） |
| 解析语义 | 平台内解析（agent 运行侧注入） | `resolve(ref)` → `{value, source}`——**每次操作重解析**（轮换即时生效） | token 刷新（托管） |
| UI 安全 | 值不回显 | `describe(ref)` → `{configured, source, writable}`——**视图无值槽** | 托管不可见 |
| 来源层 | 平台托管 | env / file / project-env / user-env 优先级层 | 平台会话 |
| 变更事件 | — | `credentials/reference-updated (ref)` | — |
| 授权流 | — | authorization 组（插件拥有的 OAuth——ask a human） | 平台 OAuth |

**最小公约数**：引用名不嵌值 + 解析层分离 + UI 安全视图 + 变更事件——四者是
生产凭据服务的骨架；OAuth 托管流是平台级（Chronotope 不做托管，留 provider
侧）。

## 二、Chronotope 现状差距

| 现状 | 差距 |
|---|---|
| .env 全局共享 + litellm master key | 无 org/agent 作用域隔离——多租户泄露面全局 |
| env 变量注入（适配器子进程） | 值在部署层——**无法按 agent 绑定不同凭据** |
| llm_calls 有 run/session 归属 | **无凭据维度**——审计链缺「谁用了哪个 key」 |
| 手工改 .env 重启 | 无轮换——无「新引用 + 吊销」机制 |
| 明文 .env | 无加密存储层 |

## 三、设计（三层分离对齐）

### 层 0（原语）

```
CredentialRef = 不可变引用名（POSIX 风格——dsh 同款 nominal brand）
- 进 spec digest 的是引用名（值永不过 digest）
- 进 run 快照的是引用名（bound.credential_ref——旧 run 沿旧引用）
- 值永不出现在：快照 / 事件流 / 日志 / 配置自省
```

### 层 1（策略缝）

```
CredentialResolver（策略缝）：
  Resolve(ctx, orgID, ref) → { value, source }   // 每次操作重解析——
                                                  // 轮换即时生效（dsh 同款）
  Describe(ctx, orgID, ref) → { configured, source, writable }  // UI 安全
                                                                 // ——值无槽
参考实现：DefaultCredentialResolver
  - 来源层优先级：agent 绑定 → org 绑定 → project-env → user-env → file
    （dsh 的层语义）
  - 多后端：env / PG 加密列 / 外部 secret store 指针（Vault/云 KMS 的
    最小抽象——指针不存值）
```

### 层 2（参考实现）

```
credentials 表（org 级注册）：
  org_id, ref（名字）, backend（env|pg|external）, backend_ref（指针）,
  rotated_at, state（active|revoked）
- 注册 = 引用可用；revoked = 解析返回未配置（describe 可见状态）
- 变更事件：credential.updated（org_id, ref）——reference-updated 对应
- API：POST/GET /orgs/{org}/credentials（值只在 POST 的写路径——
  读路径永远 describe）
```

## 四、装配与审计

- **注入通道**：harness 适配器的 env 注入改「引用名 → resolver 解析 →
  子进程 env」（适配器进程只见解析后的值——不进仓库/快照/日志）
- **审计**：llm_calls 加 `credential_ref`（使用归属——账本的凭据维度；
  轮换后旧 run 的历史归属不漂移）
- **轮换**：新引用 + 吊销旧引用——run 快照沿旧引用（**旧 run 的解析仍
  成功直到吊销——与 harness 升级的 draining 语义同族**）；吊销后旧 run
  的解析返回未配置 → 显式失败（不静默换凭据）

```
① 引用层 ✅（2026-10-12——CredentialRef nominal brand + EnvResolver +
   AgentConfig.CredentialRef + bound 冻结 + 033 llm_calls.credential_ref
   + PutLLMCallResult 归属落账）
② 存储层 ✅（2026-10-12——034 credentials 表 + Register/List/Revoke +
   POST/GET/revoke API——读路径永远 describe 值无槽 +
   TestCredentialLifecycle）
③ 注入通道 ⏳（适配器的引用解析注入）
④ 轮换审计闭环 ⏳（吊销语义的 worker 侧 + 变更事件 + 审计查询）
① 引用层（低成本高价值）：AgentConfig.credential_ref 字段（进 digest 是
  引用名）+ DefaultCredentialResolver（env 后端先行——零行为变化
  fallback 到现有 .env 注入）+ llm_calls 的 credential_ref 归属
② 存储层：credentials 表 + PG 加密列/外部指针 + POST/GET API（读路径
  永远 describe）
③ 注入通道：适配器的引用解析注入（dsh/Claude/Codex/Pi 四适配器）
④ 轮换与审计闭环：吊销语义 + 变更事件 + 审计查询（org 的凭据使用
  报告）
```

## 六、诚实边界

- **不做 OAuth 托管流**（Claude managed 的平台级登录态——provider 侧
  的能力；Chronotope 的 authorization 组形态后置）
- **不做值的透明加密的承诺**（PG 加密列是后端之一——生产推荐外部
  secret store 指针）
- 凭据的**跨 org 共享不做**（引用按 org 作用域——多租户隔离是默认）

## 七、验收

- 引用进 digest/快照（值不出现——grep 断言）
- 轮换：新引用生效 + 吊销后旧 run 显式失败（e2e）
- 审计：llm_calls 的 credential_ref 归属查询
- UI 安全：describe 无值槽（API 断言）
