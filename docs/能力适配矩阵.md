## 三、Chronotope 适配性评估

| 维度 | 评估 |
|---|---|
| 三层分离的容纳度 | 高——四平台的能力都落层 0/1/2：原语（快照/幂等键/HITL digest）+ 策略缝（HarnessResolver/ApprovalRouter/BudgetPolicy）+ 业务语义（参考实现）。**无一个平台能力落在三层之外** |
| 可对账性的优势 | 四平台的重放策略（Pi replay / dsh 声明）都弱于 effect ledger——**Chronotope 是它们缺失的地板**（评审二结论的再次实证） |
| 会话语义的优势 | run bound 快照 + 哈希链 + journal 重放——四平台的 session/thread/conversation 都是 Chronotope 会话的子集 |
| 生态厚度的差距 | dsh 的 Cordis 插件树（composition + patch + 自省）与 Claude 的 skills/plugins 生态厚度超过 Chronotope 的 harness_registry——**扩展层是最大短板** |
| 工具语义的差距 | Pi 的 tool execution lifecycle（duration/update）与 Claude 的 hooks 注入上下文比 Chronotope 的 mcp_calls 状态机更细——**duration 与注入是待补** |
| 可观测的差距 | Claude 的 OTel 与 dsh 的 dump-config 自省比 Chronotope 的事件流更体系化 |

## 四、双向增强规划（按序）

### A. 适配高价值特性（适配器桥接——每项低成本）

1. **hooks 注入上下文** ✅ 已落地（2026-10-11——ToolCall.ApprovalContext +
   ApprovalRequest.Context + RunAwaitingApproval 事件的 context 键 +
   Claude PreToolUse 的 class 2 参数摘要注入 + TestToolCallApprovalContext）
2. **tool execution duration** ✅ 已落地（2026-10-11——030 迁移 mcp_calls
   加 duration_ms + PutMCPCallResult 带 duration 参数 + dispatchMCP 测
   耗时（Pi 的 tool_execution_end.durationMs 对应））
3. **sandbox presets 映射** ✅ 已落地（2026-10-11——AgentConfig.Sandbox
   声明进 spec digest + riskClassOf 的取严（read_only 时写工具提级
   class 2；full_access 不放宽）+ Codex 适配器读 context.sandbox 三态
   映射 + TestSandboxPresetTighten）
4. **steering 语义** ✅ 已落地（2026-10-11——031 迁移 session_steers 表 +
   EnqueueSteering/ListPendingSteerings/ConsumeSteerings（入队序 + 消费
   幂等）+ POST /sessions/{sid}/steer 显式端点 + runLoop 的 step 前 drain
   （journaled——重放回放同一 drain）+ TestSteeringQueue）
5. **subagent ownership**（Pi/dsh）→ child run 的 ownership 字段（foreground/background——影响审批路由）

### B. 补齐 Chronotope 缺失能力（平台侧新增——每项中成本）

1. **harness 能力声明协议**：harness_registry 的 capabilities 从自由数组升级为**结构化声明**（hooks 支持/steering 支持/工具族/sandbox 预设——worker 按声明路由——dsh Seam 的运行时形态）
2. **扩展层（extensions registry）**：tools/prompts/hooks 的**可装配包**——org 级注册 + agent 绑定（Claude skills/plugins 与 dsh 插件树的最小公约数）——**harness_registry 的姊妹表**
3. **task graph 语义**：WorkItem 加依赖/状态机（Pi 的 child tasks 与 Claude 的 todo 的最小语义——M2 的演进）
4. **OpenTelemetry 导出**：事件流的 OTel span 导出（llm_call/tool_exec/step 三 span 族——Claude cost tracking 的对应）
5. **配置自省 API**：GET /orgs/{org}/config 的 composed 树导出（dump-config 形态——三层分离的可观测）

### C. 后置（触发式——量级/生态）

- session fork + handoff（Pi 的 fork/reset 完整语义——需会话的写时复制）
- 凭据命名组（dsh credentials 形态——secret 引用而非嵌入）
- 流式终态外事件透传（Claude streaming 的完整双端——需 run 事件的 SSE 广播协议）
