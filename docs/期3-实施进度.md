## 分层原则（已确认）

基础设施底座三层分离：**层 0 原语**（tenant/principal/保护性限流/中性计量/运行态原语——无业务语义）→ **层 1 策略缝**（BudgetPolicy/ApprovalRouter 接口，默认 = 无限/全过）→ **层 2 参考业务层**（billing/欠费冻结/审批策略——自带示范，可整体替换）。运行时永不硬编码业务语义。

## 沙箱生命周期闭环（D1-D4，诊断驱动）

**问题诊断**：每次 e2e 后大量容器/卷残留——生命周期半闭环：executor 经
Docker API 创建沙箱（compose 生命周期之外）+ Destroy 不删 named volume +
无启动 sweep（崩溃窗口孤儿）+ 测试停栈杀掉 GC 循环。实证：577 卷 + 237
容器残留（本机磁盘打满元凶）。

**修复**：D1 Destroy 连卷（rm -f + volume rm）；D2 executor 启动 sweep
（label 扫孤儿 vs DB 行：无行/已 destroyed/过期 → 清，ready 保留交 GC）；
D3 e2e 编排收尾 trap 显式清（测试环境确定性）；D4 一次性清理（256 容器 +
596 卷清零）。**验证：全量 CI 回归后孤儿容器 0 / 卷 0（此前每轮几十个）**；
E2B driver sweep 空操作（E2B 侧 TTL 自动回收）。
