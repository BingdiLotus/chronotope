## A. 用户层身份与计费对齐

### A.1 目标与现状

- **目标**：org → user 两级身份；user 级配额（run 数/限流）与用量归属；api key 挂 user（scopes 已预留）。
- **现状**：api_keys(id/org_id/key_hash/scopes)；org 日预算三级熔断；Limiter 有 org/user 桶的注释位但只实现 session 桶。

### A.2 设计

1. **迁移**：`users(id, org_id, name, quota_daily_token/…)` 或复用预留列——MVP 剪裁：`users` 表（org_id, name, quota map jsonb）+ api_keys 加 `user_id` 可空列（旧 key = org 级）。
2. **身份链**：api 认证中间件已解析 org（API_AUTH_MODE）→ 扩为解析 `(org, user)`；请求上下文携带。
3. **user 级限流**：Limiter 加 user 桶（新桶 1 run/5s 默认，可配）；session 桶保留（三层：org/user/session）。
4. **计费对齐**：usage 表加 `user_id` 可空列（回填规则：按 run 归属）；`GET /orgs/{org}/usage` 支持 `?user_id=` 过滤；org 预算检查不变（快照语义 ⑧）。
5. **MVP 剪裁**：不做注册/登录流程（key 创建时可选绑 user）；不做 user 级日预算熔断（先限流 + 归属），user 预算后置。

### A.3 验收

- 单测：key 绑 user 解析、user 限流 429 + Retry-After、usage 按 user 过滤。
- e2e：双 user 隔离（A 的 run 不计入 B 的 user 用量；限流互不影响）。

## B. 审批策略路由 + 审计留存

### B.1 目标与现状

- **目标**：审批请求可路由（按 tool/风险/阈值选审批人集合）、过期自动拒绝、审批全程审计留存。
- **现状**：class 2 → request_approval（digest 精确绑定 + approver 留痕 + audit.approval）；webhook 任意非空文本可批准（legacy 兼容）；无过期。

### B.2 设计

1. **审批策略**：`org_approval_policies(org_id, tool_pattern, class, approver_emails jsonb, ttl)`——MVP：org 级一条默认策略（`PUT /orgs/{org}/approval-policy`）+ 按 tool 前缀匹配（数组）。
2. **路由**：webhook resolve 时查策略 → 校验 approver ∈ 策略集合（不在 → 拒绝 + audit.approval_denied）；legacy 兼容保留（无策略时任意非空）。
3. **过期**：pending 槽记录 created_at → webhook resolve 时超时（默认 24h）→ 自动拒绝 + `run.failed{approval_expired}` + 事件；worker 侧挂起不动（零成本语义不变）。
4. **审计留存**：`audit.approval`/`audit.approval_denied`/`audit.approval_expired` 事件 + `GET /orgs/{org}/audit?kind=approval`（按事件类型过滤的审计导出——复用 audit 事件查询）。
5. **MVP 剪裁**：单策略（无复杂规则引擎）；email 通知后置（outbox 已有通道，接 SMTP 时随投递）。

### B.3 验收

- 单测：策略匹配/approver 校验/过期拒绝矩阵。
- e2e：设策略 → 非成员 approve 被拒 → 成员 approve 通过；TTL 调小 → 过期自动拒绝（audit.approval_expired）。

## C. MCP 网关

### C.1 目标与现状

- **目标**：MCP 接入的租户级权限面——工具 allowlist、按 org/user 授权、调用审计集中。
- **现状**：worker 托管 MCP 客户端（ConnectMCP 对象状态 + tools/list 缓存 + mcp.call 事件）；连接凭 org 隔离（session → org）；无工具级白名单。

### C.2 设计

1. **工具 allowlist**：`mcp_allowlists(org_id, server, tool_pattern)`——连接时校验工具清单，未列工具不下发（worker 的 tools/list 过滤）；空 allowlist = 全拒（默认安全）。
2. **授权面**：ConnectMCP 的 api 端点校验 org 权限（现有认证）+ allowlist 落库（`PUT /orgs/{org}/mcp-allowlist`）。
3. **审计集中**：mcp.call 事件已存在 → 加 `GET /orgs/{org}/audit?kind=mcp`（复用 B 的审计导出）。
4. **MVP 剪裁**：stdio 沙箱内进程后置（继续远程 HTTP 服务器）；MCP 规范会话语义对接后置（Streamable HTTP 客户端已支持基础）。

### C.3 验收

- 单测：allowlist 过滤矩阵（空=全拒/前缀/全量）。
- e2e：设 allowlist → 未列工具调用被拒（tool_denied 事件）→ 加列后通过。

## D. 记忆三层化 + 共享知识库

### D.1 目标与现状

- **目标**：工作记忆（窗口）/ 长期记忆（会话条目）/ **共享知识（org 级，pgvector 检索）** 三层；共享知识跨会话挂载。
- **现状**：summaries + memory_items（会话级，topic 作用域 + recency 检索，无嵌入）；pgvector 镜像已备（extensions 未启用）。

### D.2 设计

1. **迁移**：`org_knowledge(id, org_id, content, embedding vector(1024), source_session, created_at)` + pgvector 扩展启用；`CreateOrgKnowledge/RetrieveOrgKnowledge(org, query_embedding, topK)`。
2. **嵌入**：harness 加 `POST /embed`（LiteLLM 的 embeddings 端点代理）——MVP：真实模型 embedding（.env 有密钥）；fake 模式确定性向量（单测用）。
3. **挂载**：buildMessages 注入检索片段（org 级 topK=3，按 run 的 topic 查询）——`POST /orgs/{org}/knowledge`（写入）+ 消化时自动沉淀后置。
4. **三层化**：会话记忆保持；共享知识标注 `kind=shared` 的条目同时写入 org_knowledge（`PUT /orgs/{org}/knowledge/from-memory?session=`）——MVP：手动提升 + 直接写入两条路。
5. **MVP 剪裁**：不做自动巩固（sleep-time consolidation 后置）；不做跨 org 共享。

### D.4 验收

- 单测：嵌入检索 topK 相关性（fake 嵌入：同主题向量近邻）、知识写入/提升。
- e2e：写入共享知识 → 新会话 run → harness 请求的 messages 含注入片段（llm.call 载荷断言）。
