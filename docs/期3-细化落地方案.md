## 0. 分层总览：基础设施底座的三层分离

本项目定位为基础设施底座，用户/治理层按三层建模（与 LiteLLM 网关 vs 预算、Lago/OpenMeter 计量 vs 计费、K8s admission 策略缝同构）：

```
层 0 基础设施原语（运行时只认这些——无业务语义）
  tenant（中性隔离边界）· principal（技术主体：key/user/service-account）
  保护性限流（防滥用，与钱无关）· 中性计量（usage 事件流）
  运行态原语（paused/frozen/awaiting 挂起等待外部信号——通用能力）
        ▲ 策略缝（业务规则的插入点；默认无业务 = 无限/全过）
层 1 BudgetPolicy.Check(snapshot)→{Allow|Hold} · ApprovalRouter 审批人路由
  计量订阅（usage 经 outbox 投递业务层）
        ▲
层 2 参考业务层（本项目自带，示范 + 默认可用，可整体替换）
  billing account/plan（日预算/订阅）· 欠费冻结策略 · 审批策略
```

**核心原则**：运行时永远不硬编码「预算/欠费/审批人」——业务语义经策略缝注入；自带参考实现保证默认可用，业务方可替换。

## A. 租户/主体原语 + BudgetPolicy 策略缝

### A.1 目标与现状

- **目标**：① tenant 语义收敛（隔离边界，与钱解耦）；② principal 化（key/user 都是技术主体，scopes 权限 + 保护性限流）；③ 预算判定从 run 循环抽成 `BudgetPolicy` 接口（默认允许一切，现有 org 日预算降级为参考实现）；④ usage 中性计量 + principal 归属。
- **现状**：`orgs` 表含 quotas（业务）；worker runLoop 入口硬编码 org 日预算检查（⑧ 已快照化）；api_keys 无 user 维度；Limiter 只有 session 桶。

### A.2 设计

1. **BudgetPolicy 接口**（worker 侧新包 `internal/policy`）：
   ```go
   type Decision struct { Allow bool; Hold string /* await 信号名 */ }
   type BudgetPolicy interface {
       // 入口快照判定（⑧ 语义：快照 + run 内累计确定性；Hold = 挂起等待信号）
       Check(ctx, snapshot BudgetSnapshot, acc Accum) Decision
   }
   ```
   - `BudgetSnapshot` = 现 budgetSnapshot 泛化（去掉 org 业务字段，保留配额/用量视图）。
   - 默认实现 `AllowAll`；参考实现 `OrgDailyBudget` = 现有逻辑平移（读 org quotas + 冻结 awakeable——**冻结槽本身是层 0 原语**，参考实现只是调用它）。
   - worker 装配点：env/配置选择策略（`POLICY_BUDGET=org-daily|none`）。
2. **tenant 语义收敛**：orgs 表保留（迁移成本最小）但契约/注释明确「基础设施租户」；`orgs.quotas` 声明为**参考业务层数据**（无参考策略时忽略）。
3. **principal 化**：`users(id, tenant_id, name)` + api_keys 加 `user_id` 可空；认证中间件解析 `(tenant, principal)`；usage 行加 `user_id` 可空（按 run 归属回填）。
4. **保护性限流**：Limiter 加 principal 桶（默认 1 run/5s，可配）——与计费无关的滥用防护；session 桶保留。
5. **计量订阅**：usage 事件（已有 llm.call/sandbox.exec/run.* 事件流）经 outbox 投递——业务层记账的通道（本期只确认通道存在，订阅方后置）。

### A.3 验收

- 单测：BudgetPolicy 接口矩阵（AllowAll / OrgDailyBudget 平移等价——原预算单测全数迁移到参考实现）；principal 解析/限流；usage 按 user 过滤。
- e2e：w5-budget 不回归（参考实现默认装配）；双 principal 隔离（A 的用量不计入 B）。

## B. ApprovalRouter 策略缝 + 参考审批策略

### B.1 目标与现状

- **目标**：审批人路由经 `ApprovalRouter` 接口（默认 = 控制台人工/无路由）；参考实现 = org 审批策略（approver 集合 + TTL 过期自动拒绝）；审计留存。
- **现状**：class 2 → request_approval（digest+approver 绑定 + audit.approval）；无路由/过期语义。

### B.2 设计

1. **ApprovalRouter 接口**（`internal/policy`）：`Route(ctx, ApprovalRequest{tool, class, session}) → []Approver`；默认 `ManualOnly`（空集合 = 控制台人工）。
2. **参考实现 `OrgApprovalPolicy`**：`org_approval_policies(tenant_id, tool_pattern, class, approvers jsonb, ttl)`——webhook resolve 校验 approver ∈ 集合（非成员拒绝 + `audit.approval_denied`）；TTL 过期 → 自动拒绝 + `run.failed{approval_expired}` + `audit.approval_expired`。
3. **审计留存**：`GET /orgs/{org}/audit?kind=approval`（audit.* 事件类型过滤导出）。
4. **MVP 剪裁**：单策略（无规则引擎）；email 通知后置（outbox 通道已备）。

### B.3 验收

- 单测：Route 矩阵（默认空/策略匹配/approver 校验/TTL 过期）。
- e2e：设策略 → 非成员拒绝 → 成员通过；TTL 调小 → audit.approval_expired。

## C. MCP 网关（基础设施安全面）

### C.1 目标与现状

- **目标**：MCP 接入的租户级**技术权限面**（allowlist 属基础设施安全——非业务语义）——工具白名单、审计集中。
- **现状**：worker 托管 MCP 客户端（ConnectMCP + tools/list 缓存 + mcp.call 事件）；无工具级白名单。

### C.2 设计

1. **工具 allowlist**：`mcp_allowlists(tenant_id, server, tool_pattern)`——连接时过滤工具清单；**空 allowlist = 全拒（默认安全）**。
2. **审计集中**：`GET /orgs/{org}/audit?kind=mcp`（复用 B 的审计导出）。
3. **MVP 剪裁**：stdio 沙箱内进程后置；MCP 会话语义对接后置。

### C.3 验收

- 单测：allowlist 过滤矩阵（空=全拒/前缀/全量）。
- e2e：设 allowlist → 未列工具 tool_denied → 加列后通过。

## D. 记忆三层化 + 共享知识库

### D.1 目标与现状

- **目标**：工作记忆（窗口）/ 长期记忆（会话条目）/ **共享知识（tenant 级，pgvector 检索）**；共享知识跨会话挂载——作为基础**数据服务**（存储+检索），业务方自行决定沉淀策略。
- **现状**：summaries + memory_items（会话级，topic+recency 检索，无嵌入）；pgvector 镜像已备。

### D.2 设计

1. **迁移**：`tenant_knowledge(id, tenant_id, content, embedding vector(1024), source_session, created_at)` + pgvector 扩展；`CreateKnowledge / RetrieveKnowledge(tenant, embedding, topK)`。
2. **嵌入**：harness 加 `POST /embed`（LiteLLM embeddings 代理）；fake 模式确定性向量（单测）。
3. **挂载**：buildMessages 注入 topK=3 检索片段；写入 API `POST /orgs/{org}/knowledge` + 记忆条目提升 `kind=shared`。
4. **MVP 剪裁**：自动巩固后置（sleep-time consolidation）；跨租户共享不做。

### D.3 验收

- 单测：检索 topK 相关性（fake 嵌入近邻）、写入/提升。
- e2e：写入共享知识 → 新会话 run → llm.call 载荷含注入片段。
