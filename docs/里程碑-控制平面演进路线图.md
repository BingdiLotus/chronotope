# 下一里程碑演进路线图：从持久执行运行时到可审计控制平面

> 2026-10-09 定稿。输入：长周期 Agent 控制平面文章（CSDN）+ 三份外部评审 +
> 生态事实调研（LoopX v0.2.7 / pi-durable / dsh / Kitaru / Restate 融资 /
> langgraph-ledger 竞争实证）。
> 原则：不再修细节；产品功能演进；每个里程碑有验收证据，不与文档 ✅ 混淆。

## 一、定位修正（三份评审的共识）

| 旧叙事 | 新叙事 |
|---|---|
| 「时空可组合持久运行时」（底座） | **可审计的持久执行语义**——「别人 harness 底下那层不能少的东西」+ **多租户托管版控制面**（LoopX 是单机本地状态内核——你做托管多租户） |
| 与 dsh 同说「时空」 | 明确区分：dsh/Cordis 是**组件级**时空（可逆效应/依赖拓扑）；Chronotope 是**会话级**时空（事件 seq/checkpoint 树/workspace 对象图）——买家关心的是「一周前的会话今天还能继续、副作用没重跑」 |

**三态谱系叙事**（现成的差异化）：可逆（进程内，Cordis 管）→ 可补偿（进程外，**你的效果账本**）→ 不可逆留痕（append-only，**你缺哈希链——M1 补**）。不混用「可逆」与「补偿」两词。

## 二、资产盘点（对齐材料诊断，不自我怀疑也不虚标）

**比材料更硬的既有资产**：durable execution 真 journaled（68 处 restate.Run）、effect ledger + prepared/done + 输入摘要、ComputeLease + generation fencing、HITL digest 精确绑定 + TTL、三层分离纪律、append-only 事件流。

**结构缺口**（评审三的诊断单）：

- 六对象：有 2.5（Gate 半成品——阻塞整个 session 而非动作域；Claim 是资源级非动作级；Quota 缺调度语义）——**缺 3**：Goal（带 version）、WorkItem、Evidence（带 revision/expiry）
- BVT 七步：READ/EXECUTE/VALIDATE/WRITEBACK/ACCOUNT 已有——**缺 DECIDE 与 CLAIM 动作级扩展**
- **scheduler 顺序反了**：定时器到点 → 起 run → 烧 token 后发现没事干——应为 DECIDE 先行（run/wait/ask/replan/repair/quiet），定价模型是活跃 session 时长时这就是毛利问题
- 三处弱实现：deliveries/{id}/ack 是 stub；记忆检索无嵌入（与 pgvector 知识库不对称）；ForkSession 全量复制（rollback 不回滚空间面）
- 两必答：PG LISTEN/NOTIFY 未接（多副本失效）；internal/policy 零测试（治理能力没测试等于没有）
- checkpoint 快照失败静默退化（session_ops.go:66）——计费/SLA 的不可接受静默失败

**竞争证据（2026-10 实测）**：[Restate 融资 $27M 进银行/Replit](https://startuply.vc/article/restate-s-27-million-runtime-wires-durable-ai-agents-into-replit-and-fortune-500-i8jgt2)（赛道成立）；[langgraph-ledger](https://pypi.org/project/langgraph-ledger/0.2.0/) 已出现（框架自下而上抢 effect ledger——**对冲动作是 M4/M5**）；[Pi durable harness 上 Cloudflare](https://developers.cloudflare.com/changelog/post/2026-10-02-pi-harness/)（harness 商品化实证——不能靠 harness 竞争）。

## 三、里程碑路线图

### M0：可观测经济学基线（先做——「真实数据比架构图有说服力」）

**为什么先做**：买家只在乎真实负载下的成本/延迟/失败模式；定价模型（活跃 session 时长）的生死在唤醒经济学。

- 真实模型 + 真实 E2B 的**负载基线**（已有 w17 4/4 与 real-e2e 9/9 的基础——扩展为 N 并发 × 长任务的成本/延迟/失败模式测量）
- **休眠/唤醒经济学数字**：挂起一周的 session 唤醒 P50/P99、存储 GB、$/session-hour 毛利测算——公开
- checkpoint 快照失败静默退化 → **显式降级事件**（计费与 SLA 面）
- **验收**：一页数字（唤醒延迟分布 / 存储成本 / 单位经济），不是文档

### M1：防篡改审计 ✅ 已落地（2026-10-09）

- 026 迁移：events 加 prev_hash/event_hash/hold；AppendEvent 事务内写
  sha256(prev||type||payload) 哈希链
- GET /sessions/{id}/audit-export + scripts/audit-verify.sh 独立链验证
  （任一行改/删即失败——审计师工具）
- POST /sessions/{id}/audit-hold 法定保留（hold 行不可删护栏）
- 验收达成：TestAuditChainIntegrity + 本地 CI 21/21

### M2：对象模型补全 + DECIDE 先行 ✅ 已落地（2026-10-09）

- **层 2** 补三对象：Goal（objective/scope/version/owner/status——跨 session 的慢变量，Session 是执行上下文）、WorkItem（description/priority/dependencies/task_class）、Evidence（blob_hash + produced_at/valid_for/source_revision/expires_at/验证方法——新鲜度是 blobstore 的补完）
- **层 0** 扩两原语：Claim 作用域从沙箱扩到**动作级**（agent_id/scope/expires_at/capabilities——与 lease 同族不可绕过）；DECIDE 接缝（控制面 API——业务语义留层 2）
- **DECIDE 先行**：scheduler_hint 进 Quota/Policy 缝——定时器到点 → DECIDE（run/wait/ask/replan/repair/quiet）→ 才起 run（顺序反转）
- **「不作为的可问责性」**：DECIDE 的每一次「不运行」判定 journaled（「为什么没动」的审计轨迹——LoopX 类应用层控制面拿不到，durable workflow 白送）
- 每个新对象配状态前后 hash + 事件 + 投影可重建（不重开刚闭合的正确性）
- **验收**：VTR/TPVT/Stale Evidence Reuse Rate/Duplicate Work Rate 从事件日志**投影**（不可伪造——相对 APM 打点的碾压性）

### M3：窄切口合规验收 demo（评审一第 3 条——停止宣传底座）

- 选一个 continuity 本身就是产品的场景：**受监管企业 VPC 内的 coding/运维 agent**（数据不出网 + 审计）或**长周期带审批的资金/工单类 agent**（效果账本 + approval digest 已落地）
- 验收 = 「客户拿它过合规评审」
- 同时补三处弱实现：deliveries ack 真实化、记忆检索接 pgvector（两套能力对称）、fork 父指针 + 合流（空间面纳入同一指针模型——顺手补 rollback 不回滚空间面）
- 两必答穿插：internal/policy 补测试（M2 前）；PG LISTEN/NOTIFY 接入（多副本部署——M3 前）

### M4：契约公开标准（唯一对冲「框架吃掉你」的护城河）

- 四份契约独立版本号 + changelog；executor/harness **一致性测试套件**（第三方自证兼容）；参考实现清单
- **R3 接缝**：executor capability 命名 Seam（一等公民——dsh/Pi 零侵入接入验证：它们的 tool seam 对上你的 execute 幂等键）
- 验收：第三方按 /runs 协议实现 harness 的走通记录

### M5：薄嵌入形态（竞品从「平台」变「依赖」）

- 效果账本 + journal + checkpoint 抽成**可嵌入库/sidecar**（用户自带 Claude Agent SDK / OpenAI Agents SDK 的 harness——/runs 契约本就支持 0 平台改动换 harness）
- 验收：一个「薄运行时包住任意框架」的参考集成（对照 Kitaru 路线——但你多了可对账性）

## 四、依赖与优先级

```
M0（数据）────────┐
                  ├──→ M2（对象模型+DECIDE）──→ M3（合规 demo）──→ M4（标准）──→ M5（嵌入）
M1（哈希链审计）──┘         │
                            └── policy 测试、PG LISTEN 穿插完成
```

- M0/M1 可并行（数据与工程独立）；M2 是核心枢纽；M3 依赖 M1+M2；M4/M5 依赖 M2 稳定
- **纪律保持**：并发原语进层 0（Claim 动作级/DECIDE 接缝/scheduler_hint 类型），业务语义留层 2（Goal 达成定义/Gate 触发策略/Quota 分配策略）——不背叛三层分离

## 五、风险与对冲

| 风险 | 对冲 |
|---|---|
| 框架自下而上（langgraph-ledger 已现） | M4 契约标准 + M5 薄嵌入——成为框架底下那层 |
| 厂商自上而下（托管平台加幂等账本） | 自托管/反锁定 + M1 防篡改审计（他们不做） |
| 再去做 harness（pi-durable/dsh 教训） | 定位纪律：火花在「成为它们底下那层」 |
| 结构化状态成为新错误源（文章自警） | 每对象配 hash+事件+投影可重建；别急着铺开 |

## 六、一句话

地基（durable/event sourcing/lease/fencing/补偿）已超前于对象模型——**现在补对象模型比补地基便宜得多**。M0-M1 证明「真实数据 + 不可篡改」，M2 把 LoopX 的单机控制面变成**多租户、不作为也可审计**的托管版，M3-M5 把它从底座变成标准与依赖。

## 附：M0 经济学快速验证方案（2026-10-09 定稿，待执行）

> 完整 M0（N 并发 × 长任务真实负载 + 数天挂起唤醒）耗时数周；拆成
> 「机制可快测 + 成本可账面投影」后可压缩到 **1-2 天**。核心洞察：
> **挂起时长 ≠ 唤醒延迟机制**（延迟=快照恢复的机制性延迟，与挂起时长无关；
> 挂起时长只影响存储量）。

### 第 1 天：唤醒经济学（合成大工作区）

1. 生成合成 workspace（500MB / 1GB 两级）+ 快照 → 销毁沙箱
2. 唤醒（快照恢复）计时 P50/P99 + 存储大小记录
3. 结论：唤醒延迟分布 + GB/规模曲线 + 每 GB 恢复成本
4. 复用：w2-snapshot / w10-timetravel 的恢复链；w17 真实 E2B 路径证据

### 第 2 天：空转成本 + 单位经济投影

1. **空转率测量**：fake 模型测「无新证据唤醒」的一次空转成本（token 固定 =
   prompt 大小——真实模型测一次 prompt token 即可，不需真实长周期）
2. **单位成本投影器**（CLI 脚本）：三账本 SQL 聚合 × 公开价格
   （模型 API 价格 + E2B 计算秒 + S3 存储）→ 每 session-hour 成本/毛利
   ——账本来源：llm_calls（token）、events（duration_ms 计算秒）、
   workspace_files / RustFS（存储）
3. **scheduler_hint 节省估算**：空转率 × 单次空转成本 × 唤醒频率
   = DECIDE 先行能省的金额（M2 立项依据）

### 产出（验收即一页数字）

唤醒 P50/P99、GB/周存储、$/session-hour 毛利、空转率与 DECIDE 节省——
建立在已有资产上（w17 / real-e2e / 三账本），不需要计费系统或数周挂起。
