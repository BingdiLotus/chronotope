# 适配器特性桥接规划（充分发挥四平台特性）

> 2026-10-12 规划定稿（先文档后编码）。背景：四批 SDK 适配完成了「真实
> SDK 跑通 + 账本闭环」的 MVP——**特性的桥接只做了最小三个**（PreToolUse
> 注入、sandbox 映射、usage）。本规划把能力矩阵调研的 21 能力族**逐项桥接
> 到适配器**——每个特性在 Chronotope 语义下闭环（不是 SDK 单独跑通）。
> 原则：正确性相关的特性先行；双份权限取严在 SDK 侧完整执行；三铁律
> 边界不破（SDK 内部状态不持久化——续跑从 /runs 入参重建）。

## 一、现状盘点（已用 vs 未用）

| 适配器 | 已用 | 未用（本规划桥接） |
|---|---|---|
| Claude | query + 文本/工具块 + usage + PreToolUse 注入 | permissions、hooks 全族、checkpointing、subagents、skills、streaming input、structured outputs、MCP |
| Codex | thread 新建 + run + sandbox 声明 | resumeThread、approvals、app-server、security |
| Pi | submit/wait/AssistantEntry | beforeToolCall、replay 策略、tool lifecycle、inbox 注入、child tasks、compaction、fork |
| dsh | headless 的 text/final/usage | tool_use、subagent 多后端、credentials 组、session persistence |

## 二、批 A（正确性相关——双份权限取严与工具幂等的 SDK 侧执行）

### A-1 Claude permissions ✅（2026-10-12——permission_mode="custom" + canUseTool 回调（class 0 allow / class 2 ask 双层审批 / 其余 allow）+ SDK 返回工具名规范化（Bash→bash 词汇表）；SDK 侧 ask 默认拒绝——class 2 工具 SDK 侧零执行 + tool_call 交棒平台审批 = 双层取严完整链）

- **桥接**：SDK 的 `permission_mode="custom"` + `canUseTool` 实现——工具名
  的 allow/deny/ask 三态按 Chronotope 的 class 分级判定（class 0 → allow、
  class 2 → ask（触发 SDK 侧审批）+ 平台 HITL 双层、其余 → allow）。
- **验证**：class 2 工具在 SDK 侧被 ask（hook 事件断言）+ 平台审批后执行
  ——双份权限取严的完整链。

### A-2 Pi beforeToolCall ✅ 桥接落地（2026-10-12——pi-durable 的 hook(ToolTask, {beforeTool})：class 2（bash/run_python）→ {block: reason}——block 语义 = 工具零执行 + error tool result（官方）；replay 策略声明在 defineTool 侧后置标注；验证受阻于批 3 的代理 key 细节（Provider is not configured）——key 解后 w27 验证 block 的零执行断言）

- **桥接**：pi-durable 的 harness 配置 `beforeToolCall`——class 2 工具返回
  `{block: true, reason}` → 工具不执行 + 审批挂起帧（A1 的 ApprovalContext
  通道复用）；`terminate: true` → run 停止的映射；AgentTool 的
  `replay: "never"|"safe"` → Chronotope 的 prepare 声明对齐（账本的幂等
  键策略声明化）。
- **验证**：block 的工具零执行（账本无 dispatched 行）+ replay 声明进
  快照。

### A-3 dsh tool_use ✅ 桥接落地（2026-10-12——tool_call/tool_result 事件解析（官方 --json 形态实证：callId/tool/input + status/result）+ tools_used 清单进 done 帧（平台账本可见的 dsh 工具行为）；完整交棒（工具进 Chronotope executor——headless 自执行的形态限制）后置标注——需 dsh-sdk-client 的 stdio 逐 turn 协议）

- **桥接**：headless --json 的 `tool_use`/`tool_result` 事件 → tool_call
  帧（execute 幂等键）——dsh 的工具调用进 Chronotope 的 executor/MCP。
- **验证**：dsh 侧的工具调用经 Chronotope 执行（沙箱 exec 闭环）+ 账本
  dispatched/done。

## 三、批 B（会话语义——四平台的会话能力对齐）

### B-1 Codex resumeThread（会话续跑）

- **桥接**：run 的 messages 历史 → SDK 的 `resumeThread(threadId)`——
  threadId 映射为 Chronotope 的 runID（三铁律边界：thread 不持久化——
  每次 run 从入参重建 messages 再 resume）。
- **验证**：多轮对话的上下文连续（第二轮引用第一轮的内容——真实续跑）。

### B-2 Pi fork/compaction（分叉与压缩的 SDK 侧）

- **桥接**：Pi 的 fork conversations → Chronotope 的 session fork 调用；
  compaction → memory consolidation 的触发（阈值语义的对齐）。
- **验证**：fork 后的独立演进 + compaction 后的摘要注入。

### B-3 Claude checkpointing（file rewind → checkpoints 映射）

- **桥接**：SDK 的 checkpoint 事件 → Chronotope 的 checkpoints 坐标
  （file 级 rewind → 快照坐标的对应）。
- **验证**：rewind 后 run 的恢复与账本的一致性。

## 四、批 C（生态——平台的差异化优势）

### C-1 Claude skills/plugins/MCP（生态工具的 SDK 侧装配）

- **桥接**：SDK 的 skills → Chronotope 的 skills 字段（已有一致）；
  plugins → B2 扩展层的映射；MCP 连接 → Chronotope 的 MCP 工具
  （SDK 的 MCP 与平台的 MCP 对齐）。
- **验证**：skill 的 SKILL.md 加载 + MCP 工具的调用闭环。

### C-2 dsh subagent 多后端（spawn 的多宿主）

- **桥接**：dsh 的 subagent 工具（inprocess/spawn/acp/codex/claude-code/
  dsh-sdk）→ Chronotope 的 spawn_subagent 的多宿主（executor 注册表
  的能力路由）。
- **验证**：不同后端的子代理派发（ownership 语义的完整）。

### C-3 Codex security SDK（扫描 → Evidence）

- **桥接**：security SDK 的 repo/change 扫描 → Chronotope 的 Evidence
  （结构化安全发现 → 证据链）。
- **验证**：扫描发现进证据链（M2 的 Evidence 查询）。

## 五、每批的验收基线

- **特性在 Chronotope 语义下闭环**（不是 SDK 单独跑通——账本/HITL/快照
  的对应断言）
- **三铁律边界不破**（SDK 内部状态不持久化——续跑/恢复从 /runs 入参
  重建）
- **双份权限取严**（SDK 侧与平台侧的判定都过——不互相豁免）
- **e2e 固化**（w29+ 的段——真实 SDK 特性的回归）

## 六、诚实边界

- Claude 的 platform 托管（OAuth/managed agent）不做——provider 侧
- Codex 的 app-server 完整形态（auth/history 的托管客户端）后置——
  需平台级部署
- dsh 的 ACP/typert（协议与类型注册的生态层）后置——触发式
- Pi 的 hooks/extensions 的完整插件机制后置——B2 扩展层已是最小公约数

## 七、分阶段落地顺序

```
批 A（正确性）：A-1 permissions → A-2 beforeToolCall/replay → A-3 tool_use
批 B（会话）：B-1 resumeThread → B-2 fork/compaction → B-3 checkpointing
批 C（生态）：C-1 skills/MCP → C-2 subagent 多后端 → C-3 security
```
