# 错误分类与可观测性（应用契约 v1.0.0）

> 机器可读错误集合：[contracts/application-contract.v1.json](./contracts/application-contract.v1.json)。
> 本文说明 Bots 如何分支、Chronotope 记录什么、以及哪些内容绝不进日志/指标。

## 1. 分类模型

| category | 含义 | 典型 error_code | 默认 retryable |
|---|---|---|---|
| `validation` | 请求/配置/契约非法 | `invalid_request`、`validation_failed`、`invalid_application_config`、`output_schema_violation` | false |
| `auth` | 认证/租户/operator 权限 | `unauthorized`、`forbidden`、`tenant_mismatch`、`admin_required` | false |
| `not_found` | 资源不存在或跨 scope 不可见 | `not_found` | false |
| `conflict` | 幂等冲突/忙碌/状态冲突/路由不可变 | `idempotency_conflict`、`session_busy`、`target_route_immutable` | 仅 `session_busy` true |
| `rate_limit` | 限流 | `rate_limited` | true |
| `provider` | 模型/harness 上游失败/超时/限流/截断 | `provider_error`、`provider_timeout`、`provider_rate_limited`、`model_output_truncated` | 条件 true |
| `tool` | application bridge 失败或结果未知 | `application_tool_error`、`application_tool_result_unknown` | false |
| `timer` | timer target 改址/撤销/回调未确认/提交失败 | `timer_target_changed`、`timer_target_unavailable`、`timer_callback_unknown`、`timer_callback_rejected`、`timer_ack_persist_failed`、`timer_submit_failed` | 回调/提交类 true；fencing 类 false |
| `runtime` | store/事件/历史/IPC 内部错误 | `internal_error`、`service_unavailable`、`store_error`、`event_error` | 5xx true；run 终态 false |
| `limit` | 步数/预算/deadline/无进展 | `max_steps`、`budget_exceeded`、`deadline_exceeded`、`no_progress` | false |
| `policy` | 审批/策略拒绝 | `tool_denied`、`approver_revoked` | false |
| `canceled` | 显式取消 | `canceled` | false |

HTTP 状态与 error code 不一致时，`writeErrorCode` 按状态回退到通用码，绝不会
返回“status 422 + 一个声明为 500 的 code”这种自相矛盾信封。

## 2. retryable 的严格含义

`retryable=true` 只回答一个问题：**在稳定幂等键下重试同一逻辑操作是否安全？**
它不保证 run 可恢复，也不保证外部效果未发生。契约 v1 之前的历史 run 结果可能
缺少 `category/retryable`；Bots 应按 `category=runtime, retryable=false` 降级，
不得猜测为可重试。

- `session_busy`：应用持久排队；原 run 终态后用**同一 Idempotency-Key** 重试。
- `rate_limited`/`service_unavailable`/`upstream_error`/`upstream_timeout`：
  指数退避 + 同一 key；不得换 key 绕过未知结果。
- run `provider_error`/`provider_timeout`/`provider_rate_limited`：
  - 只有在该 run **尚未发生任何 application tool 批次**时才 `retryable=true`；
  - 已发生工具批次后一律 `retryable=false`，因为工具可能已产生外部效果。
- `application_tool_result_unknown`：**永不自动重做**。应用按
  `operation_id`（tool bridge 的 Idempotency-Key）对账/人工裁决。
- timer 回调失败：`retrying` + `last_error_code` 由 Restate 重投同一
  `fire_id`；应用必须幂等接纳。`blocked` 不重投，等待 target 恢复或人工处理。
- 幂等冲突 `idempotency_conflict` / `target_route_immutable`：修正逻辑请求或
  重新登记 ref，不是“退避重试”。

### Bots 映射建议

```text
error_code == idempotency_conflict      -> 修正请求；保留原 key，不新建逻辑操作
error_code == session_busy              -> 入本地持久队列，完成后同 key 重试
category == rate_limit                  -> 退避 + jitter，同 key
category == provider && retryable        -> 新 run 仅在本地确认无外部效果时提交
application_tool_result_unknown          -> 停止自动流程，按 operation_id 对账
timer.state == blocked                   -> 不再重计时；按 last_error_code 告警
```

Bots 自己的 list_tasks/list_reminders、memory 查询/forget 属于应用工具与 PG
状态；Chronotope 只透传工具结果，不解释其业务错误。

## 3. 关联视图

所有运行日志/指标允许的关联键：

| 键 | 来源 | 用途 |
|---|---|---|
| `run_id` | run 主键 | run 延迟、终态、provider/tool 关联 |
| `session_id` | session 主键 | 会话时间轴 |
| `tenant_id` | bound run / target row | 租户隔离与审计 |
| `operation_id` | `sha256(run_id, step, tool_call_id)` | 应用工具幂等/对账 |
| `tool_call_id` | harness tool_call | 单次工具调用 |
| `tool_ref` | agent 固定工具表内部引用 | bridge 延迟/失败 |
| `timer_id`/`revision`/`fire_id` | timer 行 | 提交/回调/重试 |
| `target_ref` | bridge/timer target | 路由与 fencing |

**禁止**进入日志或指标标签：Authorization/Bearer token、service token、租户
key、模型请求/响应正文、工具 arguments/result 正文、Slack ID/频道/消息正文、
opaque application payload。日志只记录长度/摘要/分类等有界字段。

## 4. Structured log 事件

统一 `log/slog` key-value；事件名稳定，字段只增不改。

| 事件 | 级别 | 关键字段 |
|---|---|---|
| `run.terminal` | Info/Warn | run_id, session_id, tenant_id, status, error_code, category, retryable, steps, duration_ms |
| `provider.error` | Warn | run_id, tenant_id, step, model, error_code, category=provider, duration_ms |
| `tool.bridge` | Info/Warn | run_id, tenant_id, operation_id, tool_ref, outcome=success/unknown/error, error_code, duration_ms, result_bytes |
| `timer.admitted` | Info | tenant_id, timer_id, revision, target_ref, state |
| `timer.submit` | Warn | tenant_id, timer_id, revision, error_code=timer_submit_failed, retryable |
| `timer.fire` | Info/Warn/Error | tenant_id, timer_id, revision, fire_id, target_ref, state=acknowledged/retrying/blocked, error_code, blocked, duration_ms |
| `target.registered` | Info | action=create/update, tenant_id, kind, ref, revision, actor |
| `target.revoked` | Info | tenant_id, kind, ref, actor |

`provider.error`/`tool.bridge` 不含上游响应正文；`timer.fire` 不含 callback URL
或 token；`target.*` 不含 URL 正文中的凭据（URL 本身已禁止 userinfo）。

## 5. Metrics

API `GET /metrics`、worker `GET /metrics`（Prometheus text；无租户维度，避免
把 tenant 变成高基数标签）。

| 指标 | 类型 | 标签 |
|---|---|---|
| `chronotope_http_errors_total` | counter | status, error_code |
| `chronotope_run_terminal_total` | counter | status, error_code, category, retryable |
| `chronotope_run_duration_seconds` | histogram | status |
| `chronotope_provider_errors_total` | counter | code |
| `chronotope_provider_call_duration_seconds` | histogram | outcome |
| `chronotope_tool_bridge_total` | counter | outcome, error_code |
| `chronotope_tool_bridge_duration_seconds` | histogram | outcome |
| `chronotope_timer_admission_total` | counter | outcome |
| `chronotope_timer_fire_total` | counter | state, error_code |
| `chronotope_timer_fire_duration_seconds` | histogram | state |
| `chronotope_application_target_changes_total` | counter | kind, action |

指标在 replay 时可能重复计数（至少一次语义）；只用于趋势/告警，不作为计费或
幂等真相。run/timer 的真相仍是 PG 行、事件日志和 Restate journal。

## 6. 排查顺序

1. `GET /runs/{id}`：看 `status`、`error.error_code/category/retryable`；
2. 按 `run_id` 查 `run.terminal`/`provider.error`/`tool.bridge` 日志；
3. 按 `operation_id` 查应用侧账本，区分“未执行/已执行/结果未知”；
4. timer：`GET /timers/...` 看 `state`、`last_error_code`、`fire_id`；
5. target 问题：查 `application_targets` + `application_target_audit`，确认
   ref/revision/digest 与 timer 行冻结的 `target_digest` 一致；
6. 仍不能解释时，再查 Restate journal（Sleep/fire 位置），不要用日志正文推断
   外部效果。
